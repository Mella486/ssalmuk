# Workflow

- Whenever files in this repo are edited during a session, commit and push immediately (to `origin`/`main`) without asking for confirmation first. The user wants local edits reflected on the live site (GitHub Pages) right away — don't batch changes or wait to be told to commit.
- Still use clear, conventional commit messages describing the change. Only exception: pause and ask if a change looks destructive/risky beyond normal content edits (e.g. force-push, history rewrite, deleting something not obviously meant to be deleted).
